# Interpreter Live 1.1.1 (4) — text speech fallback and playback integrity

Two press-and-hold buttons: Russian → German and German → Russian.

While pressed, AVAudioEngine records the built-in microphone (24 kHz mono PCM16)
and immediately streams 200 ms audio frames over one WebSocket to
`/v1/realtime/translations?model=gpt-realtime-translate`.
No second real-time-length upload occurs after releasing the button.
Pending microphone frames queue while the socket connects.
On release, the app drains the final frame and sends `session.close`.
It receives audio and transcript deltas until `session.closed`.

Translated audio is buffered while the microphone is active, then played
incrementally once the button is released and translation text is available,
using AVAudioPlayerNode. This prevents the phone speaker from feeding back
into the microphone. Unconfirmed audio (no transcript) is not auto-played.
Playback does not wait for the full transcript or the full `session.closed`.

In 1.1.1, the stream player checks that the ordered PCM bytes scheduled for playback
match the PCM bytes received from OpenAI (length and rolling fingerprint). It also
stops with a visible warning instead of silently discarding a buffer when playback
cannot schedule it. This checks the app's playback pipeline, **not** whether the
speech's German/Russian words match the translation transcript.

After a transcript has finished, **Озвучить текст перевода · голос iPhone · бесплатно**
reads precisely the visible translation text using iOS `AVSpeechSynthesizer`, in
the target locale (`de-DE` or `ru-RU`). It requires no API request, speech
recognition permission, or separate subscription. The built-in system voice will
sound different from OpenAI's streamed translation voice. The original server audio
is still available under **Прослушать снова** for a free comparison.

The source recording is retained as original PCM data wrapped in WAV for
optional listening/export. The finished translated recording can be replayed
offline without another API request. Input noise reduction and extra
transcription are disabled. No extra paid model calls or retries. The local speech fallback is user-initiated.

The input cap is 60 seconds, old requests are cancelled on a new press or
backgrounding, and API key remains in the device-only Keychain.
The balance and costs are estimates, not verified OpenAI billing figures.

Build: `cd Live && xcodegen generate`, scheme `InterpreterLive`.
GitHub Actions builds simulator and iPhone unsigned IPA. It is not an
on-device integration test: latency, audio route and spoken translation must
be verified on iPhone before treating this version as production-ready.

## iPhone acceptance checks for 1.1.1

1. Translate Russian to German and German to Russian. After receiving the complete transcript, tap **Озвучить текст перевода** and verify that the system voice speaks the visible text in the correct language.
2. Compare **Прослушать снова** (OpenAI's original stream) to the on-device system voice. Neither replay nor system speech should use new API credits.
3. Tap a new talk button while the system voice is speaking: it should stop cleanly. Also test backgrounding and reopening the app.
4. Test audio streaming with long phrases, pauses, and a Bluetooth audio route. PCM scheduling failures must show a visible warning and preserve the original server recording for replay.
5. A coherent but semantically wrong answer generated by OpenAI cannot be caught by the byte audit. Compare the original Russian recording, visible German transcript, and original sound when investigating translation accuracy.

The GitHub CI builds are compile/protocol checks, not proof of audible behavior on an iPhone.
